# Test audit adapter

The vendored `test-audit` skill comes from another repository and names that repository's files, commands and workflow. Read each of its references through this table; everything else in the skill applies as written.

| The skill says                                                               | In VolleyBro                                                                                                                                                                                                                                                 |
| ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| boundary and cost guide (`docs/help/testing/writing-tests.md`)               | [`docs/testing-strategy.md`](../testing-strategy.md): its tier table decides the owner boundary, and its Test Value section is the authoring gate this skill serves.                                                                                         |
| proof policy (`openclaw-testing`)                                            | Run the owner test and its siblings with the tier's runner: `pnpm test <path>` for a unit test, `pnpm test:integration <path>` for an `.itest.ts`, `pnpm test:workflow` for `scripts/`. Before the pull request, `pnpm verify:all` is the gate.              |
| active Vitest checkouts                                                      | Does not apply: VolleyBro runs Jest and `node --test`.                                                                                                                                                                                                       |
| `pnpm deadcode:dependencies`, `deadcode:unused-files`, `deadcode:exports`    | `pnpm knip`, which reports unused files, exports and dependencies in one run.                                                                                                                                                                                |
| autoreview                                                                   | The `code-review` skill. Its Standards axis applies this skill's rules to the diff.                                                                                                                                                                          |
| commit, push or land through the native maintainer workflow                  | `WORKFLOW.md`: the delivery mode chosen at intake, merged only through its human gate.                                                                                                                                                                       |
| a subsystem such as `extensions/telegram`, or one core area (campaign lanes) | One owner area of `src/`: a layer (`entities`, `applications`, `infrastructure`, `interface`) or one feature's slice across them. A Sharded Change batch that deletes or moves tests runs as a campaign, with the ledger `docs/testing-strategy.md` defines. |
